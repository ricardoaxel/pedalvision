# ADR-003: Catalog data & asset strategy

**Status:** Accepted (2026-09-22) · amended 2026-10-14 (committed seed = real facts + mocked images; schema-originality + taxonomy + ingestion model; per-item source links) · amended 2026-10-15 (render direct official brand image URLs where recorded; mock is the fallback) · amended 2026-10-21 (self-hosted public-asset policy; capture-once raw archive; master inventory + 2,000 cap; pedalboards first-class) — ⚠️ MUST BE REVISITED BEFORE ANY PUBLIC LAUNCH

## Context
The app needs pedals/boards with real footprint dimensions + top-down transparent PNGs. Research (Sep 2026) found no dataset with a clean image licence. A comprehensive community catalog exists (~8.5k pedals, ~250 boards, inches + 350/800px PNGs), but its repo has **no LICENSE file** (default copyright) and its maintainer has objected to unpermissioned reuse before.

Two different things are in play:
- **Facts** — brand names, product names, footprint dimensions. These are public information (manufacturer/brand pages, retailers) and are not the aggregate's creative work.
- **Images** — the transparent top-down PNGs are the part that is genuinely theirs and cannot be reused.

**The external aggregate is never referenced** — its name/URL must not appear in code, commits, filenames, comments, or shipped assets (owner instruction, 2026-09-22). **Amended (owner decision, 2026-10-14):** **per-item source links** ARE now recorded in the catalog data (`sources: [{ url, kind }]`, see §Per-item sources) so every verified fact is traceable to the source(s) it was checked against (manufacturer/authorized preferred). The aggregate itself is still never cited.

## Decision
1. **Committed dev seed = real catalog facts + procedurally mocked images** (owner decision, 2026-10-14).
   - The committed seed (`src/catalog/data/{pedals,boards}.json` + `public/pedal-assets/**`) uses **real brand names, product names, and footprint dimensions** derived from the public community catalog. Rationale (owner): that information is a convenience index of public facts, not proprietary creative work. The earlier invented/synthetic items are **removed**.
   - **All images are procedurally mocked** (shapes + bitmap label, drawn by `tools/catalog-transform`). No third-party image files are downloaded, committed, or served. Images are the single piece gated on clearance.
   - **Effect types are two-tier and OURS (not from the source).** The aggregate carries no effect taxonomy, so `effectTypes` is our own vocabulary (`EFFECT_TYPES` in `src/catalog/schema.ts` — sound effects + non-effect roles like `preamp`, `buffer`, `di`, `ab-box`, `amp-modeler`). It is filled by (1) a **verified override table** (`tools/catalog-transform/curated.ts`, keyed by base-model slug; colorway variants inherit the base) sourced from manufacturer/vendor facts, and (2) a deterministic, intentionally conservative keyword classifier (`tools/catalog-transform/effects.ts`) that leaves creatively-named pedals unclassified rather than guessing. The committed seed equals `deriveEffectTypes()` for every pedal (guarded by a no-drift test).
   - **Accepted risk:** the aggregate has no licence and its maintainer previously objected to reuse. The owner accepts this for the **dev seed only**. Before public launch the catalog must be cleared (see exit criteria).
   - The seed is generated by the generic CLI `tools/catalog-transform` (input/output always CLI args) and **committed as static JSON + procedural PNGs**, so fresh clones and CI need no external data. The seed is a **subset** today (top brands); the full catalog is backfilled later (see the task's follow-up note).
2. **Our own schema** (design.md §Data model) is source-agnostic. The transformer converts an external catalog JSON → our schema (inches→cm, name-keys→stable slugs, flat duplicates→model+variant). We do not inherit external conventions or field names.
3. **Before public launch**, the catalog uses the **owner-approved self-hosted public-asset policy** (2026-10-21, §Self-hosted public-asset images): quality-gated images hosted by us, with a per-item source URL and an attribution/takedown path. Written permission is **no longer a launch gate** (owner accepts responsibility); the earlier permission-first / brand-outreach path is superseded.
4. Every catalog item carries a `source` tag (`licensed` | `brand-assets` | `community` | `own` | `public-asset` | `placeholder` | `synthetic`) so the launch gate is machine-checkable. The committed dev seed uses **`placeholder`**; `public-asset` is added in P5-01 for hosted public imagery.
5. **Procurement ownership (S4):** catalog procurement is now part of **P5-01** (policy/data contract/inventory), with the owner approving the public-asset policy + attribution/takedown and **P5-05** choosing image hosting at scale. The launch gate below sets a **minimum-content bar** so "launch" can't mean "launch with 2 pedals".

## Per-item sources (owner decision, 2026-10-14)

Every verified fact is traceable to the source(s) it was checked against,
recorded in an optional `sources` array per item:

```jsonc
"sources": [ { "url": "https://<source>/...", "kind": ["info", "image"] } ]
```

- **Authoritative-first, not official-only.** Manufacturer/authorized sources
  are preferred; a reputable retailer/magazine or community/vintage archive may
  appear as *corroboration* (this mirrors the source hierarchy below). URLs must
  be `http(s)`.
- `kind` is a non-empty array: `"info"` = backs specs / effect type / release
  date; `"image"` = a candidate source for the product image. A single URL may
  be both (e.g. a manufacturer product page). Under the 2026-10-21 policy the
  image pipeline downloads, quality-gates, processes and self-hosts the asset;
  the URL remains the per-item provenance.
- Populated for the **verified** base models — the `curated.ts` keys plus models
  whose official image source was resolved. **176 of the 187 base models carry
  at least one source ref; 170 of them have an `image`-kind link.** The seed
  carries **485 source refs, 340 of them `image` links**. Sources live on the
  **base** model; a colorway variant (`variantOf`) resolves to its base's
  sources (not duplicated). Unverified items have none — their facts come only
  from the aggregate, which is never cited.
- This **amends** the earlier blanket "no URLs in catalog data" rule: the
  *aggregate* stays uncited; *per-item* source links are allowed and wanted.
- The URL is the per-item provenance; the site also provides a general
  attribution/takedown page (2026-10-21 policy). The agent returns the link, the
  curation stores it.

## Brand image URLs (owner decision, 2026-10-15 — superseded for P5 by §Self-hosted public-asset images)

> Historical/interim: this hotlink rule still describes the 129 legacy `url`
> seed items until P5-03 replaces them. P5 images are self-hosted `static`.

**Where a direct official image URL is recorded, render it directly instead of a
mock; the procedural mock is now the *fallback only* (items with no usable URL).**
Provisional and pre-clearance — it lets the app show real gear while development
continues, without waiting for P5-02.

- **How:** a direct-file `image`-kind source (`sources[].url` ending in
  `.jpg/.jpeg/.png/.webp/.gif/.avif`, not an HTML product page) is promoted to the
  render image: `image = <url>`, `imageSource = "url"`. Implemented by the
  `resolve-images` transformer command (pure `resolveImages()` in
  `tools/catalog-transform/images.ts`); deterministic, idempotent. The render
  contract is design.md §Assets (image-resolution contract).
- **No download / no scraping:** only the URL already recorded in `sources` is
  reused; nothing is fetched or committed — this is *hotlinking* an official
  manufacturer asset, not copying it.
- **Rights still pending:** items render a brand URL but keep `source:
  "placeholder"` — the launch gate is unchanged (cleared assets only). P5-02
  later replaces each `url` with a cleared `static` file (or drops it).
- **CORS is a render-time concern:** images load with `crossOrigin="anonymous"`,
  so CORS-clean hosts display (and keep the canvas untainted for export);
  non-CORS hosts (and hosts that block hotlinking) fall back to the labeled
  silhouette. A failed URL is never broken — it just falls back.
- **True-scale bar:** the image is stretched to the item's exact cm footprint, so
  only a **top-down, tightly-cropped cutout** (transparent/canvas-neutral
  background, no shadow) keeps true scale. Angled "hero" shots and padded product
  photos do not — a known provisional inconsistency; they stay mock until cropped
  (or are replaced in P5-02).
- **Boards:** same rule; official board image URLs were researched + recorded in
  `sources` (7 of 10 — 3 discontinued models have no official image).
- **Temporary dev-only exception (owner-directed, 2026-10-15):** a small set of
  local top-down test images were added as committed `static` files for
  development (and to ship nicer example renders), to be **deleted later**. They
  are `source: "placeholder"` (not cleared) and do **not** change the rights
  policy or the launch gate; the pipeline's "no download" rule (§no scraping)
  still governs the catalog itself. Remove them by reverting the `imageSource`
  to `url`/`mock` and deleting the files.

## Self-hosted public-asset images (owner decision, 2026-10-21)

This **supersedes** the permission-first / hotlink-only rules for the P5 catalog program. The owner accepts responsibility for sourcing and publishing catalog images; the site will provide attribution and a takedown/removal path.

- **Hosting:** every shipped image is a **static asset we host** (`imageSource: "static"` under `public/pedal-assets/`, or the CDN chosen in P5-05). **P5 delivery format is AVIF** (`.avif`, q80 default / q90 escalation); PNG stays valid for mocks, legacy seed assets and a per-item fallback. Hotlinked `url` images are legacy seed data and are replaced during P5-03. Same-origin (or CORS-clean CDN) keeps canvas export working.
- **Candidate sources:** official manufacturer product/press pages first; authorized retailers/product pages second; existing public catalog images as a **last-resort candidate**. No bulk copying of another site's descriptions; factual data is re-verified.
- **Per item:** keep the source URL in `sources` (`kind: ["image"]`), plus a **`public-asset`** rights tag (added to `SOURCE_TAGS` in P5-01). `source` no longer means "written permission"; it records the provenance class.
- **Attribution + takedown:** a visible credits/attribution page and a removal-request contact; removal requests are honoured and the affected assets are replaced or dropped.
- **Quality gate:** resolution, uniform/transparent background (remove **all** non-product background-coloured areas — white, black or any colour — including enclosed slots/holes; never over-key product lettering/knobs), top-down crop, aspect ratio vs the cm footprint (accept ~≤10%, flag 10–15%, reject >15%), rotation/skew, shadow/perspective checks, **and a clean-alpha gate (no white/black/any-colour halo, fringe or jagged edge — prefer an already-transparent clean planner PNG and process it with `--matte none`, never re-keying a transparent source)**; rejected candidates are re-sourced (max 3) or flagged. **Drop shadows/reflections are not part of the product:** prefer a shadow-free candidate; if the only candidate has one, remove it before trimming — never include it in the cutout or the cm footprint. **AVIF q80 must pass PSNR ≥ 40 dB and a 1:1 original-vs-compressed review; otherwise escalate q90 → q100 or keep PNG.** The BOSS AC-3 white-background and TC Choka bad-crop/shadow cases are regression fixtures.
- **Hard cap:** **2,000 pedals with hosted images** (~4,000 files, ~300 MB) until **P5-05** (image hosting at scale) is decided. Agents stop at the cap; data/image work does not continue past it.
- **Optional jack layout:** capture **every** connector the source exposes (audio I/O, aux, expression/CV, MIDI, USB, power) with `jacks[]` (`kind`, `edge`, `pos`, `stereo?`); only audio I/O (`in`/`out`/`send`/`return`) is a cable anchor today, the rest are future-feature data. `pos` is 0..1 along the edge and is derived from exact cm (`x / widthCm` on top/bottom, `y / heightCm` on left/right), so measured edge positions are representable exactly. This is **optional enrichment**, not mandatory. If only the edge/count is known (e.g. “2 on top”), omit `pos`; exact positions win; edge-only jacks go in the middle of the largest remaining gap and are marked **approximate**. When no jack data exists at all, P4-02's fallback anchors apply (assumed IN left / OUT right).

## Master inventory & raw research archive (P5-01, owner-approved 2026-10-21)

The catalog is built **capture-once**: research writes a raw record with every
verified fact + source page + image candidate, and the runtime catalog is a
deterministic projection. Adding a runtime field later is a mapping change, not
a new research pass.

- Raw archive: `data/catalog/research/{pedals,boards}/<brand>/<batch>.json`;
  schema `src/catalog/rawSchema.ts`; contract
  `docs/catalog/raw-research-record.md`.
- Master inventory: `data/catalog/inventory.json` (off-runtime) from the
  discovery lists — **8,557 pedals / 779 brands** and **263 boards / 38 brands**;
  normalized/deduped to **8,549 pedals** and **263 boards**, with colorway
  `variantOf` links and Tier A/B/C.
- **Tier A = 1,850 pedals + exactly 150 boards** (priority-brand order, hard
  caps). The first 2,000 catalog items are ~1,850 pedals + 150 boards. Tier B =
  next brands + priority overflow; Tier C = the long tail.
- Seed validation: `data/catalog/seed-validation.json` classifies every seed
  item keep / repair / replace / drop (the 207 + 10 seed facts are kept; images
  are replaced under the public-asset policy).
- Caps: **2,000 hosted pedals** (~4,000 files, ~300 MB) until P5-05; board
  images are a separate **150-board / ~300-file / ~20 MB** budget.
- Community jack maps: `docs/catalog/jack-map-record.md` (pending/approved/
  rejected; v1 prefilled GitHub issue/PR, v2 backend). Approved maps only.
- Attribution/takedown page: `docs/catalog/attribution-takedown.md` (owner
  approved the policy; the visible page ships before launch).

## Pedalboard catalog (P5, first-class)

Pedalboards are part of the P5 catalog, not a side list. The discovery list has **263 boards / 38 brands**; the first 2,000 catalog items include **150 boards** alongside ~1,850 pedals.

- **Mandatory:** id, brand, name, `widthCm`/`heightCm` (footprint width × depth), image, source.
- **Optional raw metadata:** thickness/max height, weight, material, board type (flat/angled/tiered/folding), tiers/tier heights, surface, bag/case, power-supply mount, cable routing/clearance, handles/feet/mounting, max pedal height, lifecycle, videos, sources, confidence.
- **Images:** top-down empty board, neutral/transparent background; aspect check vs `widthCm/heightCm`; angled hero shots rejected.
- **Priority:** Pedaltrain, Pivotal, Temple Audio, Creation Music, GigRig, Morton, Rockboard, Vertex, Mono, STRICH, Aclam, Friedman, Gator, BOSS, D'Addario, Voodoo Lab, Fender, Blackbird, plus Harley Benton/Palmer/Fame/SKB/Holeyboard.

## Serial numbers, videos, artist association & price (optional, model-level)

- **Price:** if a source already shows a price, record `priceObservations: [{ amount, currency, condition: new|used, source, observedAt, notes }]`. It is an observation, not a canonical fact; never infer a price or run a separate price search.
- **Artist association:** if a source already states that a pedal/board is a signature model, designed with an artist, or notably used by one, record `artistAssociation: [{ artist, role: signature|endorsed|used-by|designed-with, notes, sources }]`. Optional; do **not** run a separate search for it.
- **Serial numbers:** record the model's format and known ranges/revisions (date/lot codes) only, never a specific owner's unit serial: `serial: { format, ranges: [{ from, to, year, revision }], location, notes }`.
- **Videos:** record links (not downloads) with `{ url, title, source, kind, verified }`; prefer manufacturer/official demos, manuals, then reputable reviews. Same attribution/takedown policy.

## Schema originality (our own model)

Our catalog schema (`src/catalog/schema.ts`, mirrored in design.md §Data model)
is **independently designed**, not a rename of the source's fields. The source
row shape is flat `{ Brand, Name, Width, Height }` in **inches**, with images and
no category/taxonomy. We deliberately diverge on structure, units, identity,
referentiality, and provenance:

| Source field | Our field | What we changed (why it is our model) |
| --- | --- | --- |
| `Brand` | `brand` | kept as a display string (not a joined entity) |
| `Name` | `name` + `id` | we mint a **stable slug id** (`brand-model`); name stays display-only |
| `Width` / `Height` (inches) | `widthCm` / `heightCm` (**cm**) | unit-native storage; px exists only at render time |
| — (flat duplicates) | `variantOf` | flat colorways become a **referential variant graph** |
| — | `effectTypes` | our **own taxonomy** (enum), absent from the source |
| — | `category` (`pedal`/`supply`) | device class the picker/creator need |
| — | `jacks` (`kind`/`edge`/`pos`) | cable anchoring model (S3) |
| — | `power` (`voltage`/`acDc`/`currentMa`) | power metadata |
| — | `source` (provenance enum) | machine-checkable launch gate |
| image filename | `image` | we emit **our own** `<id>.png`; source image names are ignored |

Consequences: the catalog is a **new compilation with its own selection,
arrangement, and derived content** (cm conversion, slug identity, variant graph,
taxonomy, category, mocked images). No source field names, ordering, or image is
reused. Rows missing brand/name/dimensions are dropped; duplicates are dropped
with a warning.

## Sourcing, rights & ingestion operating model

Folded in from our catalog-strategy notes (`docs/catalog-strategy-notes.md`); it does not
change the decisions above, it makes the workflow explicit.

- **Source hierarchy:** official manufacturer (product page / manual / press
  kit) first → reputable retailer/catalog for corroboration → community/vintage
  archive as lower-confidence corroboration only. Embodied by the `pedal-expert`
  agent (`.opencode/agent/pedal-expert.md`).
- **Capture once, normalize later:** research writes a raw record with **all verified facts found during the base pass**, source pages and image candidates, including fields the runtime schema does not use yet (`extra` bag). **Optional fields are opportunistic** — never run a second search just for serials, videos, artist, price, jacks, MIDI/USB, board extras, etc.; missing is fine. The raw record also captures optional **connectors/audio I/O/control/MIDI/USB/wireless/power/circuit/physical** metadata when found; the runtime catalog is a projection. The shipped catalog is a projection; later schema/UI additions map from the raw archive instead of re-researching. Never discard a verified fact because the UI does not show it yet.
- **AI assists, never invents:** extraction/normalization is machine-assisted;
  conflicts, low-confidence records, and dimension spot-checks are **human
  gates** (P5-01/P5-04 / launch exit criteria). Prefer `unknown` over a wrong value.
- **Per-item provenance (planned):** retain source, last-verification date, and
  confidence per item — extends the coarse `source` tag. Tracked as a backfill /
  data-model task (`docs/catalog-backfill.md`); not needed for the v1 seed.
- **Images use the owner-approved public-asset policy** (§Self-hosted public-asset
  images): self-hosted, quality-gated, per-item source URL, attribution/takedown
  path. The seed still ships mocked images until P5-03 replaces them; no
  placeholder may ship. Candidate sourcing prefers official sources and never
  bulk-copies descriptions. `imageSource` (`mock` | `static` | `url`) records
  **how** the image is provided; `source` records the provenance class, with
  `public-asset` added in P5-01.
- **Independent site:** Pedalvision is an independent planner; brand/model names
  are used factually with no implied endorsement. Any future affiliate links
  carry disclosure and are locale-aware (non-goal N5 today).

## Exit criteria (launch gate — required minimum; Tier A target is owner-waivable)
- [ ] **Swap the dev seed for the hosted, quality-gated catalog before deploy (S1):** no `synthetic` or `placeholder` items in the deployed catalog
- [ ] Zero `placeholder`-sourced items in the deployed catalog
- [ ] Deployed images contain no placeholder/mocked files; every shipped image is a **hosted static asset** with a per-item source URL and is covered by the attribution/takedown policy
- [ ] **Absolute minimum (S1):** ≥200 catalog pedals across ≥10 brands + ≥10 pedalboards, hosted images + sources, no placeholder/`synthetic`
- [ ] **Tier A launch target:** ~1,850 pedals + ~150 pedalboards (~2,000 catalog items) verified; launching below this requires explicit owner acceptance
- [ ] **Dimension spot-check (S6):** a documented sample (≥10 items) re-measured against manufacturer pages/spec sheets, screenshots/links recorded here — catches hand-measured footprint errors before they ship
- [ ] **Hosting gate:** the 2,000-hosted-pedal cap is respected; if launch scope exceeds it, P5-05 has chosen and verified the hosting option
- [ ] Attribution/takedown page is live and the removal contact works
