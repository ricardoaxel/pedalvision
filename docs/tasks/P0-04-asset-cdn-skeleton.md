# P0-04: Asset serving — Pages-shipped images

**Phase:** P0 · **Status:** todo · **Model:** build-cheap

## Goal
The v1 asset convention is defined: pedal/board images live in `public/pedal-assets/` (two renditions: `800/` and `350/`) and ship with the Cloudflare Pages deployment — **same-origin, no CORS setup** (ADR-002). A `src/lib/cdn.ts` helper centralizes asset URLs. R2 is deferred (not in this task).

## Read first (context pack)
- `docs/decisions/002-hosting-and-assets.md` (whole file — v1 = Pages-shipped, R2 deferred)
- `docs/design.md` §Assets & catalog

## Constraints
- No R2, no `{CDN_BASE}` env, no CORS rules in v1 — that's the deferred path (ADR-002, revisit at ~2k items).
- Images are static repo files under `public/pedal-assets/`, committed (they ship with the app). Synthetic seed images are generated by P0-05, not this task.
- `assets/` (raw pipeline input) stays gitignored; only processed `public/pedal-assets/` is committed.

## Steps
1. Create `public/pedal-assets/pedals/800/`, `public/pedal-assets/pedals/350/` (and `boards/` equivalents) with a README explaining the convention
2. `src/lib/cdn.ts`: `assetUrl(kind: 'pedal'|'board', size: 800|350, file: string)` → `/pedal-assets/{kind}/{size}/{file}` — single source of truth for URLs
3. Add a `.gitignore` rule: `assets/` (raw) excluded, `public/pedal-assets/` committed
4. Note in AGENTS.md/design.md that `pnpm assets:sync` is the R2-era tool (unused in v1)

## Acceptance (executable)
- `pnpm test`: `cdn.ts` URL builder returns the expected paths
- A placeholder 350/800 test PNG committed → `pnpm dev` serves it at the correct URL (manual check in PR)
- `grep -ri "CDN_BASE\|access-control\|R2" src` returns nothing (no R2/CORS code in v1)

## Notes
No owner blocker (no bucket, no secrets needed). When the catalog grows past ~2k items, write the R2 ADR amendment and a new `P2-07 Asset CDN (R2)` task.
